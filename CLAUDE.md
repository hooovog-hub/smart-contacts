# CLAUDE.md — инструкции для AI-агентов

Этот файл читает любой AI-агент, работающий в репозитории. Основная сессия — **Оркестратор** (Chief of Staff проекта). Она не пишет всё сама: она планирует, раздаёт задачи агентам-лидам и специалистам, собирает результат и отчитывается основателю.

## 1. Контекст проекта

- Продукт: Smart Contacts — умная записная книжка для бизнесменов (см. `README.md`).
- Рынок старта: Армения, Ереван. Языки интерфейса: русский, армянский, английский.
- Владелец и единственный, кто принимает продуктовые решения: **Ованнес**.
- Прототип: `prototype/smart-contacts-prototype.html` — эталон UX и визуального стиля.

## 2. Что читать перед любой задачей

0. `docs/07-operations/status.md` — где остановились в прошлый раз и что дальше.
1. `AGENTS.md` — кто за что отвечает.
2. `docs/01-product/PRD.md` — что строим и чего НЕ строим.
3. `docs/07-operations/roadmap.md` и `backlog.md` — что сейчас в работе.
4. `docs/07-operations/decisions-log.md` — что уже решено (не переоткрывать без причины).
5. Документы своей области (см. таблицу в `AGENTS.md`).

## 3. Как Оркестратор работает с агентами

Агенты описаны в `.claude/agents/`. Вызов — через инструмент Agent с `subagent_type: "<name>"`.

**Важно про иерархию.** Подагент не может сам запускать других подагентов. Поэтому иерархия работает так:

1. Оркестратор отдаёт задачу **лиду** отдела (например, `marketing-lead`).
2. Лид возвращает **план с назначениями**: какие специалисты, в каком порядке, с какими входными данными (формат — в `AGENTS.md`, раздел «Handoff»).
3. Оркестратор запускает специалистов по этому плану (независимые — параллельно).
4. Результаты специалистов возвращаются лиду на ревью (ещё один вызов лида с результатами).
5. Оркестратор сводит итог и сообщает основателю.

Для типовых процессов есть готовые команды в `.claude/commands/` (`/feature`, `/campaign`, `/release`, `/status`, `/sprint`).

## 4. Правила для всех агентов

- Пишите на русском в документах и сообщениях основателю; код, идентификаторы, коммиты — на английском.
- Не придумывайте факты о рынке, ценах, законах — ищите и указывайте источник, или пометьте как гипотезу.
- Не меняйте продуктовые решения молча. Если считаете решение плохим — предложите альтернативу и аргумент, решает основатель.
- Секреты (ключи API, сертификаты) никогда не попадают в репозиторий. Только `.env` и секреты Supabase/Vercel.
- Ключ Claude API используется только на сервере. В мобильном и веб-клиенте его быть не может.
- Персональные данные контактов — чувствительные. Перед любым изменением, касающимся контактов, сверяйтесь с `docs/03-architecture/security-privacy.md`.
- Каждая задача заканчивается обновлением документа, если поменялось поведение продукта.

## 5. Definition of Done (для кода)

- [ ] Соответствует PRD и спецификации фичи в `docs/01-product/features/`.
- [ ] Типы проходят (`npm run typecheck`), линтер чистый (`npm run lint`).
- [ ] Есть тесты на бизнес-логику; ключевой сценарий проверен вручную на iPhone.
- [ ] RLS-политики покрывают новые таблицы.
- [ ] Обновлены документы и `backlog.md` (статус задачи).
- [ ] Прошёл ревью `code-reviewer`, для данных и авторизации — `security-reviewer`.

## 6. Как отчитываться основателю

Коротко: что сделано, что проверить ему (ссылка/скриншот/команда), какие решения нужны от него. Без пересказа шагов.
В конце рабочей сессии обновляйте `docs/07-operations/status.md`.
