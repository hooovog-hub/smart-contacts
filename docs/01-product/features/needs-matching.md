# «Вас ищут» — запросы «Ищу» для знакомых ваших знакомых

**ID:** SC-090…SC-096 · **Приоритет:** P1 (после запуска MVP) · **Статус:** утверждено основателем 2026-11-16 (дизайн), детали экранов — черновик · **Автор:** Оркестратор по обсуждению с основателем

Строится поверх раздела профиля «Сейчас ищу» (таблица `profile_seeks`) и «Чем могу помочь» (`profiles.helps`) из параллельного пакета. Ничего из этого не дублирует: новая фича только решает, **кому ещё** показать запрос «Ищу» и **как** ему ответить.

## Проблема
Человек пишет в профиле «Сейчас ищу: дизайнера / брендинг», но это видят только те, у кого он уже есть в книжке. А тот, кто может помочь, обычно в одном рукопожатии: знакомый знакомого. В Ереване почти все знакомы через одного человека, но ни человек, который ищет, ни исполнитель об этом не знают.
Исполнителю (дизайнеру, юристу, производителю) нужен поток тёплых запросов от людей, к которым есть общий знакомый, — без холодного спама.

## Сценарии
1. **Согласие (один раз).** После обновления пользователь видит экран «Показывать ваше „Ищу“ знакомым ваших знакомых?» Кнопки «Да, показывать» / «Только моим контактам». По умолчанию — нет (ничего не меняется, пока человек не нажмёт «Да»). То же согласие = «показывайте мне чужие запросы, где я могу помочь».
2. **Ищущий** добавляет «Ищу дизайнера / брендинг» (вручную или AI-помощник предлагает — по пакету `profile_seeks`). Если согласие есть — сервер ищет исполнителей среди знакомых знакомых.
3. **Исполнитель** открывает главную → блок «Вас ищут» → карточка: фото, имя, роль Ашота, текст «Ищу дизайнера / брендинг», «Вас знакомит Карен», дата. Кнопка «Предложить помощь».
4. **Оффер.** Исполнитель пишет одно сообщение до 500 знаков (кнопка «Помочь написать» — AI составляет черновик из его «Чем могу помочь» и брендов). Отправка списывает 1 оффер из недельного лимита.
5. **Ищущий** получает оффер: профиль исполнителя (как его видят другие), текст, «Вас знакомит Карен». Кнопки «Принять» / «Нет, спасибо», в меню «⋯» — «Пожаловаться», «Заблокировать».
6. **Принять** → обоим открываются телефоны и мессенджеры друг друга, контакт создаётся в книжках обоих (`source = 'offer'`, `linked_profile_id` проставлен), исполнитель получает уведомление «Ашот принял ваше предложение». Дальше — звонок / WhatsApp / Telegram.
7. **Нет, спасибо** → исполнитель видит «Отклонено» без причины; повторно на этот же запрос написать не может.
8. **Запрос решён** (`profile_seeks.resolved_at`) → пропадает из всех лент, неотвеченные офферы закрываются со статусом «Запрос закрыт».
9. **Отзыв согласия** (Настройки → Приватность) → все мои активные запросы мгновенно пропадают из чужих лент, меня больше не подбирают исполнителем, я больше не вижу «Вас ищут». Уже принятые офферы (обмен контактами) остаются — это обычные контакты в книжке. Неотвеченные входящие офферы остаются у меня, отправить новые ко мне нельзя.

## Как считаем «знакомы» и «1 общий знакомый»
- **Прямая связь A–B** есть, если выполнено хотя бы одно:
  1. A записан у B **и** B записан у A (совпадение номера телефона в обе стороны);
  2. был обмен через QR / профиль (`contacts.linked_profile_id` в обе стороны);
  3. оба отмечены в одной комнате встречи (`room_members`).
  Односторонняя запись («Карен сохранил номер известного человека») связью **не** считается — иначе любой может «пристроиться» к чужой сети.
- **Совпадение по номеру.** При импорте и изменении книжки сервер приводит номера к виду `+374…` (та же логика, что `phone.logic.ts`) и сравнивает с `profiles.phone`. Совпадение записывает `contacts.linked_profile_id`. Номера сравниваются только на сервере, никуда не отправляются, в AI не попадают.
- **Видимость незнакомцу:** только если между A и C есть хотя бы 1 человек B с прямой связью и с A, и с C. Через 2 человека и дальше — не показываем (решение основателя).
- **Имя общего знакомого** показываем всегда (решение основателя), кроме случая, когда B выключил «Показывать меня как общего знакомого» в настройках — тогда «1 общий знакомый». Если общих несколько — показываем того, у кого тоже включено согласие, иначе любого разрешившего; «и ещё N».
- Граф хранится как отдельная служебная таблица связей (`connections`), недоступная клиенту напрямую (только через серверную функцию). Пересчёт — при импорте, QR, комнате, удалении контакта и удалении аккаунта.

## Подбор «Ищу» ↔ «Помогу»
1. **Кандидаты:** пользователи с согласием, на расстоянии ровно 1 общего знакомого (прямые контакты видят «Ищу» и так — в профиле), не заблокированные ищущим и не заблокировавшие его.
2. **Быстрый отбор (SQL):** совпадение слов и синонимов из `profile_seeks.text` с `profiles.helps`, `profiles.role`, `brands.sphere/name/description`. Берём до 100.
3. **AI-ранжирование (Claude на сервере, Edge Function):** на вход — текст запроса и для каждого кандидата только роль, «Чем могу помочь», сфера и описание брендов (без имён, телефонов, заметок — правило 5 `security-privacy.md`). Выход (structured outputs) — до 20 кандидатов с оценкой и короткой причиной («делает брендинг для ресторанов»). Порог отсечения настраивается.
4. Результат пишется в `seek_matches` (seek_id, provider_id, score, reason, via_profile_id, created_at). Пересчёт — при создании/изменении запроса и раз в сутки для новых пользователей. AI-вызовы подбора не списываются из лимита помощника пользователя (10 в сутки), но имеют свой серверный лимит.
5. Бренды и членство участвуют в подборе только у Pro/Business — как и в RLS `private.is_paid`: у Free они скрыты, значит и для подбора не используются.

## Экраны и состояния
| Экран | Состояния |
|---|---|
| Экран согласия (один раз, потом — Настройки → Приватность) | первый показ / согласие дано / отозвано |
| Главная → блок «Вас ищут» (до 3 карточек + «Все ›») | нет согласия (блок скрыт, одна строка-приглашение в настройках) / пусто («Пока никто не ищет то, что вы делаете») / загрузка / данные / ошибка |
| Список «Вас ищут» | пусто / данные / Free — карточки видны, кнопка «Предложить помощь» с замком → экран Pro |
| Отправка оффера | черновик / «Помочь написать» (AI) / лимит исчерпан («Новые офферы с понедельника») / запрос закрыт / отправлено |
| Мой запрос → «Предложения (N)» | нет офферов / есть / пауза (10 офферов — «Включить снова?») |
| Карточка входящего оффера | новый / принят (видны телефон и мессенджеры) / отклонён / жалоба отправлена |
| Мои отправленные офферы | ждёт ответа / принят / отклонён / запрос закрыт |
| Настройки → Приватность | «Показывать моё „Ищу“ знакомым знакомых» · «Показывать меня как общего знакомого» · «Заблокированные» |

Визуальный стиль — как в прототипе (тёмный минимализм). Макеты — задача для ui-designer (SC-096).

## Данные
Новые таблицы и поля (детали — `docs/03-architecture/data-model.md` при реализации):
- `profiles.discoverable boolean default false`, `profiles.discoverable_at timestamptz` — согласие и время согласия (журнал согласий).
- `profiles.show_as_mutual boolean default true` — показывать меня как общего знакомого.
- `connections (a uuid, b uuid, kind phone|qr|room, created_at)` — прямые связи, a < b. Только сервер.
- `seek_matches (seek_id → profile_seeks, provider_id, via_profile_id, score, reason, created_at, hidden_at)`.
- `offers (id, seek_id, from_id, to_id, text ≤ 500, status sent|accepted|declined|closed, created_at, answered_at)`; уникальность (seek_id, from_id).
- `blocks (blocker_id, blocked_id, created_at)`; `reports (reporter_id, target_id, offer_id, reason, created_at, reviewed_at)`.
- `contact_source` += `'offer'`.

RLS: исполнитель читает только свои строки `seek_matches` и только запросы, на которые у него есть совпадение; оффер читают только отправитель и получатель; телефон получателя отдаётся отправителю только после `accepted` (через серверную функцию, не прямым select по `profiles.phone`). Удаление аккаунта (`delete-account`) каскадно чистит все новые таблицы.

## Правила и ограничения
- **Отправлять офферы** — только Pro / Business: Pro — 5 в неделю, Business — 15 на человека (цифры — гипотеза, пересмотреть по данным через месяц). Размещать «Ищу», видеть ленту и принимать офферы — бесплатно для всех. Пока у всех Pro на 2 месяца (миграция 0008) — работает для всех.
- Один оффер от одного человека на один запрос. После «Нет» — повтор на этот запрос нельзя.
- На один запрос — максимум 10 офферов, потом он встаёт на паузу до решения ищущего.
- **Жалоба / блок** доступны на каждом оффере и каждой карточке (требование Apple 1.2). Блок — двусторонний: мы больше не видим друг друга в лентах и не можем отправлять офферы. 3 жалобы от разных людей → отправка офферов заморожена до ручной проверки; ответ на жалобу — в течение 24 часов (страница поддержки с контактом).
- Простой фильтр текста оффера (ссылки, явные оскорбления) до отправки; ссылки в оффере запрещены в MVP.
- Push «Вас ищут» — не чаще 1 раза в сутки (сводка); push «Новое предложение» и «Принято» — сразу. Push-инфраструктуры пока нет — отдельная задача (SC-095).
- В AI не уходят имена, телефоны, email и заметки.

## Риски: App Store и закон
- **App Store 1.2 (пользовательский контент):** приложениям с контентом от пользователей нужны фильтр, жалобы с быстрым ответом, блокировка и опубликованные контакты — [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/). Покрыто правилами выше. По данным стороннего сайта сравнения версий, в октябре 2026 раздел о пользовательском контенте мог быть расширен — **перед отправкой в App Store перечитать актуальный текст** (не проверено по сайту Apple).
- **App Store 5.1.1 / 5.1.2 (данные и контакты):** что именно Apple разрешает делать с телефонной книгой на сервере (сравнение номеров), **не проверено** — проверить legal-privacy-advisor в SC-070 до разработки SC-091. Гипотеза: допустимо при явном согласии и описании в политике и в Privacy Nutrition Label.
- **Закон РА «О защите персональных данных» (HO-49-N, 18.05.2015):** основное основание обработки — согласие субъекта, согласие можно отозвать — [официальный перевод (translation-centre.am)](https://translation-centre.am/pdf/Translat/HH_orenk/2015/HO-49-N_18052015_14062023_en.pdf), [копия на foi.am](https://foi.am/wp-content/uploads/2023/09/Personaldataprotectionlaw_ENG.pdf). Это совпадает с нашей моделью opt-in и отзыва.
- **Гипотеза, требует юриста:** сравнение номеров из телефонной книги затрагивает людей, которые приложением не пользуются и согласия не давали. Минимизируем: сравниваем только с номерами пользователей, давших согласие; несовпавшие номера ни с кем не связываются и никому не показываются.
- **Гипотеза, требует юриста:** показ имени общего знакомого («Вас знакомит Карен») раскрывает его связи без явного согласия. Решение основателя — показывать; смягчение — переключатель «Показывать меня как общего знакомого» (по умолчанию включён). Если юрист скажет, что нужно согласие, — по умолчанию выключаем.

## Критерии приёмки
- **Дано** у Ашота нет согласия, **когда** он добавляет «Ищу дизайнера», **тогда** запрос видят только его прямые контакты, в «Вас ищут» у других он не появляется.
- **Дано** Ашот и Лилит оба дали согласие, у них ровно один общий знакомый Карен (связь в обе стороны с каждым), Лилит — дизайнер с «Помогу: брендинг», **когда** Ашот добавляет «Ищу дизайнера / брендинг», **тогда** у Лилит в «Вас ищут» карточка Ашота с «Вас знакомит Карен», без телефона.
- **Дано** Карен записал Ашота, но Ашот не записал Карена (и нет QR/комнаты), **тогда** Карен не считается общим знакомым.
- **Дано** между Ашотом и Лилит только цепочка из 2 человек, **тогда** Лилит запрос не видит.
- **Дано** Карен выключил «Показывать меня как общего знакомого», **тогда** карточка показывает «1 общий знакомый».
- **Дано** Лилит на Free после окончания Pro, **когда** она жмёт «Предложить помощь», **тогда** открывается экран Pro, оффер не отправляется.
- **Дано** Лилит отправила 5 офферов за неделю на Pro, **когда** шестой, **тогда** «Новые офферы с понедельника».
- **Дано** Ашот принял оффер Лилит, **тогда** оба видят телефоны друг друга, контакт появился в книжках обоих с `source = 'offer'`.
- **Дано** Ашот отклонил оффер Лилит, **когда** она снова открывает этот запрос, **тогда** кнопка «Предложить помощь» недоступна.
- **Дано** Ашот заблокировал Лилит, **тогда** ни один из них не видит запросов другого и не может отправить оффер.
- **Дано** Ашот отозвал согласие, **тогда** его запросы пропадают из «Вас ищут» у всех в течение минуты.
- **Дано** Ашот удалил аккаунт, **тогда** удалены его связи, совпадения, офферы, жалобы и блоки.
- **Дано** подбор через AI, **тогда** в запросе к Claude нет имён, телефонов, email и заметок (проверяется тестом на сборку промпта).

## Этапы
**MVP фичи (P1, после запуска основного MVP):** согласие и настройки приватности (SC-090), связи по номерам и граф (SC-091), подбор (SC-092), лента «Вас ищут» и оффер с принятием (SC-093), жалобы / блок / лимиты (SC-094), макеты (SC-096). Без жалоб и блока в App Store не выпускаем.
**Позже:** push-сводка «Вас ищут» (SC-095 — нужна push-инфраструктура); оценка «помог / не помог» и рейтинг исполнителей; оффер с ценой и сроком; веб-версия ленты; фильтр по городу; подтверждение через общего знакомого («Попросить Карена познакомить»).

## Вне рамок
- Свой чат в приложении (общение — в WhatsApp / Telegram после принятия).
- Показ запросов через 2 и более человек.
- Публичный каталог исполнителей и поиск по всем пользователям.
- Платное продвижение офферов.
